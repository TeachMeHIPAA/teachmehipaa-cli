# Stripe CLI: research notes for teachmehipaa-cli

Sources: the `stripe/stripe-cli` source at commit `78a032ff933e9924ff306123fbe373c1ee885c55` (2026-11-13), shallow-cloned to `~/scratch/stripe-src/stripe-cli`, plus docs.stripe.com/cli/* (fetched 2026-11-15).
Code links are pinned to that commit (`https://github.com/stripe/stripe-cli/blob/78a032ff…/<path>`).
Repo files were read as data. Nothing was built or run.

> Note: `docs.stripe.com/stripe-cli/*` now redirects to `docs.stripe.com/cli/*`. The old `/stripe-cli/telemetry` and `/stripe-cli/keys` pages are gone (404), so the telemetry claims below come from source code only.

## TL;DR

1. Go (go.mod says `go 1.27.3`), cobra + viper + pflag, TOML config at `~/.config/stripe/config.toml`, OS keyring through zalando/go-keyring with a 0600 file fallback.
2. Resource commands (`stripe customers create --name=…`) are generated by `go generate` from a CLI-specific OpenAPI file. The generator depends on Stripe's own `x-stripeOperations` extension (`method_name`, `method_on`). Generic `NewOperationCmd` executors do the actual work at runtime.
3. Custom methods are ordinary sub-verbs: `stripe charges capture <id>`, `stripe payment_intents confirm <id>`. Path params become positional args. Body params become `--kebab-flags`, and `-d key[nested]=v` is the escape hatch.
4. Login used to be a browser "pairing code" flow that minted a 90-day restricted key. It is now RFC 8628 device-code OAuth against `access.stripe.com`, with a refresh token in the keyring and silent refresh. `--interactive` still lets you paste a key, and `--non-interactive` prints JSON for agents.
5. `listen` depends on Stripe server infrastructure. `POST /v1/stripecli/sessions` returns a websocket URL and a `whsec_` secret. Stripe signs each event server-side, and the CLI passes the headers through to `--forward-to`.
6. `trigger` is a client-side fixture runner: embedded JSON sequences of API calls with `${step:path}` references. It creates real objects, and the events come out of that as a side effect.
7. There is no auto-pagination: only `--limit` / `--starting-after` / `--ending-before`. Other request flags: `-i` sets Idempotency-Key, `-v/--stripe-version`, `--stripe-account`, `-e` expand, `-s` show headers, `--dry-run`, `--live`.
8. Output is pretty-printed, colorized JSON on a TTY and raw JSON otherwise. There is no `--format` on API calls; `--format json` exists only for `listen` and `logs tail`. Non-401 HTTP errors print the body and appear to exit 0.
9. Telemetry goes to `r.stripe.com/0` and Sentry. Opt out with `STRIPE_CLI_TELEMETRY_OPTOUT=1` or `DO_NOT_TRACK=1`. Self-update is signed and applies only to script installs. Plugins are HashiCorp go-plugin over gRPC.
10. Releases go through three GoReleaser configs: Homebrew tap, Scoop, winget, deb/rpm on Artifactory, Docker Hub multi-arch, npm optionalDeps wrapper, macOS notarization, and RSA-signed checksums.

## 1. Repo layout, language, dependencies

## 3. Resource commands generated from OpenAPI

- **Pipeline:** `//go:generate go run ../gen/gen_resources_cmds.go` at the top of [pkg/cmd/root.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/cmd/root.go). Build tag `gen_resources` ([pkg/gen/gen_resources_cmds.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/gen/gen_resources_cmds.go)).
  - Reads `api/openapi-spec/spec3.cli.json` and the preview spec ([pkg/gen/openapi_paths.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/gen/openapi_paths.go)).
  - Writes `pkg/cmd/resources/resources_gen.go` (wiring, about 1.2k lines) and `specs_gen.go` (`OperationSpec` literals, about 56k lines) from [resources_cmds.go.tpl](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/gen/resources_cmds.go.tpl) and [resource_specs.go.tpl](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/gen/resource_specs.go.tpl).
  - Also generates `pkg/requests/stripe_version_header.go`, which pins `Stripe-Version` to the spec's `info.version` (`2026-10-28.endive`) ([pkg/requests/stripe_version_header.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/requests/stripe_version_header.go)).
  - ARCHITECTURE.md still calls the output `resources_cmds.go`. The file has since been split.
- **Driven by a vendor extension, not by `operationId` or tags.**
  - The generator iterates `components.schemas` and only considers schemas that carry `x-stripeOperations: [{method_name, method_on, method_type, operation, path}]` ([pkg/spec/spec.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/spec/spec.go) `StripeOperation`).
  - Only `method_on == "service"` operations become commands. Deprecated operations and `x-stripeNotPublic` schemas are skipped.
  - A schema name like `issuing.card` yields the namespace `issuing` and the resource `card`. Paths containing `test_helpers` get a `test_helpers` sub-resource ([pkg/gen/gen_resources_cmds.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/gen/gen_resources_cmds.go) `genCmdTemplate`).
- **Naming:**
  - The resource command is the pluralized schema name via a hand-maintained switch: `capability`→`capabilities`, `balance` stays singular, everything else gets an appended `s` ([pkg/cmd/resource/resource.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/cmd/resource/resource.go) `GetResourceCmdName`).
  - Friendly aliases come from `aliasedCmds` (`line_item`→`invoice_line_item`) ([pkg/cmd/resource/alias.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/cmd/resource/alias.go)).
  - The operation command is `method_name` verbatim, so CRUD verbs and custom methods share one namespace. Example: `payment_intents` has `apply_customer_balance, cancel, capture, confirm, create, increment_authorization, list, retrieve, search, update, verify_microdeposits` ([pkg/cmd/resources/resources_gen.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/cmd/resources/resources_gen.go) lines ~350–360). `V1ChargesCapture` maps to `POST /v1/charges/{charge}/capture` ([pkg/cmd/resources/specs_gen.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/cmd/resources/specs_gen.go)).
  - The docs show `stripe customers create --email=… --name=…` and `stripe customers update cus_… -d "metadata[key]=value"` ([docs.stripe.com/cli/resources](https://docs.stripe.com/cli/resources)).
- **Param to flag mapping** ([pkg/cmd/resource/operation.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/cmd/resource/operation.go) `NewOperationCmd`):
  - Path `{params}` become exact positional args (`validators.ExactArgs(len(urlParams))`).
  - POST body properties become flags with `_`→`-`. Nested object properties are flattened to dotted flags (`--usage-threshold.gte`) by `addDenormalizedParams` ([pkg/gen/gen_resources_cmds.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/gen/gen_resources_cmds.go)). `metadata` and `expand` are deliberately skipped.
  - GET query params also become flags.
  - Types map as follows: `string`/`number` → string flag, `integer` → int flag with sentinel `-1`, `boolean` → bool flag, `array` → `StringArray`.
  - Flags carry annotations for required/mostcommon/enum/format. These are used for help grouping ("Request Parameters") and for auto-built `--help` examples (`buildExamples`).
  - `--parent[child]=value` is normalized to the dotted flag ([pkg/cmd/resource/nested_flags.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/cmd/resource/nested_flags.go)).
  - Anything not modeled goes through `-d "nested[param]=value"`, which is form-encoded for v1. For v2 paths, `-d` is parsed into a JSON body (`BuildDataForV2Request`, [pkg/requests/base.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/requests/base.go)).
- **Post-processing** for hand overrides: `PostProcessResourceCommands` patches `events` (adds `resend`), `keys`, `approval_requests` and `climate`, removes `apps`, and hides aliased names ([pkg/cmd/resource/resource.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/cmd/resource/resource.go)).
- **DELETE** asks for interactive confirmation (mode, account, connected account) unless `-c/--confirm` is passed ([pkg/cmd/resource/operation.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/cmd/resource/operation.go), [pkg/requests/base.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/requests/base.go)).

## 4. Auth and login

- **Current default flow: OAuth device code (RFC 8628).**
  - `login.Login` calls `GetLinks` on the dashboard `/stripecli/auth`. A 3xx response means the machine is enrolled in OAuth, and the CLI runs `LoginWithDeviceCode` ([pkg/login/login.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/login/login.go)).
  - Endpoints are `https://access.stripe.com/stripecli/oauth2/device/authorization` and `/token`, with `scope=stripecli` and public client id `oacli_V18aOD6v0hs9CU` ([pkg/login/oauth_device.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/login/oauth_device.go)).
  - Grant `urn:ietf:params:oauth:grant-type:device_code`, polled every 2 s, honoring `slow_down`. The browser URL prefers `verification_uri_complete`.
  - The access token ("UAT", `oak_` prefix) and its expiry go to the keyring under `uat` and `oauth_uat_expires_at`. The refresh token goes under `oauth_refresh_token`. The active account/mode context goes under `oauth_active_context` ([pkg/config/profile.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/config/profile.go)).
- **Silent refresh with rotation.**
  - `RefreshUATIfNeeded` refreshes when less than 60 s remain ([pkg/config/profile.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/config/profile.go)).
  - `refreshOAuthToken` stores the rotated refresh token. If the response omits one, it deletes the stored token. On `invalid_grant` or `invalid_scope` it wipes the credentials and asks the user to run `stripe login` ([pkg/login/oauth_refresh.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/login/oauth_refresh.go)).
  - A 401 `unauthorized` on an `oak_` token triggers one refresh and retry ([pkg/requests/base.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/requests/base.go) `performRequest`).
  - **Gap:** the refresh lock is an in-process `sync.Mutex` (`refreshMu`). Two concurrent CLI processes can race a rotating refresh token.
- **Legacy flow: pairing code that mints a restricted key ("RAK").**
  - The CLI prints a pairing code, offers to open the browser ("Press Enter…"), and polls a `PollURL` until the Dashboard confirms. It then saves a restricted key ([pkg/login/client_login.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/login/client_login.go), [pkg/login/keys/](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/login/keys/keytransfer.go)).
  - Keys get `KeyValidInDays = 90`, recorded as `test_mode_key_expires_at` / `live_mode_key_expires_at` ([pkg/config/profile.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/config/profile.go)).
  - The `api_key_expired` 401 gets a dedicated "run `stripe login`" message ([pkg/cmd/root.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/cmd/root.go) `apiKeyExpiredMessage`).
- **Agent and headless modes:**
  - `--non-interactive` is automatic when stdin isn't a TTY. It prints `{browser_url, verification_code, next_step}` JSON and exits.
  - `next_step` is `stripe login --complete '<poll-url>'` (legacy) or `stripe login --complete-device` (OAuth, with pending state saved to disk) ([pkg/login/login.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/login/login.go), [docs/cli/login](https://docs.stripe.com/cli/login)).
  - `-i/--interactive` prompts for a pasted API key ([pkg/login/interactive_login.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/login/interactive_login.go)).
  - Since v1.50, an org admin must enable "MCP and CLI access" in the Dashboard before users can log in ([docs/cli/login](https://docs.stripe.com/cli/login)).
- **Key precedence:**
  - `STRIPE_API_KEY` env, then `--api-key`, then the profile ([pkg/config/profile.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/config/profile.go), [docs/cli/api_keys](https://docs.stripe.com/cli/api_keys)).
  - `STRIPE_DEVICE_NAME` sets the device label.
  - You can also persist a key by hand: `stripe config --set test_mode_api_key sk_test_…`.
- **Profiles:**
  - `-p/--project-name` (default `default`, env `STRIPE_PROJECT_NAME`) selects a TOML table ([pkg/cmd/root.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/cmd/root.go)).
  - A v2 config layout nests profiles. Migration runs in `PersistentPreRunE` and leaves `config.toml.v1.bak` behind ([pkg/config/migrate.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/config/migrate.go), [pkg/cmd/config_migration.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/cmd/config_migration.go)).
- **Config file:**
  - Path is `$XDG_CONFIG_HOME/stripe/config.toml`, falling back to `~/.config/stripe/config.toml`. Override with `--config`.
  - Permissions are forced to 0600, with a warning if that fails ([pkg/config/config.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/config/config.go) `InitConfig`).
  - The test-mode key is stored **in plaintext in the TOML**. The live key goes to the keyring, and only a redacted copy is written to the TOML (`writeProfile`, [pkg/config/profile.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/config/profile.go)).
- **Keyring:**
  - The OS keyring is reached via zalando/go-keyring with per-call timeouts, so a hung D-Bus can't block.
  - If the keyring fails, credentials fall back to `~/.config/stripe/credentials.json` (0600). The CLI warns: "the system keyring is unavailable…" ([pkg/keyring/keyring.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/keyring/keyring.go), [pkg/login/login.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/login/login.go)). The code comment says this copies the GitHub CLI pattern.
- **Live vs test:**
  - Per-command `--live` flag, default test ([pkg/requests/base.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/requests/base.go) `InitFlags`).
  - With OAuth there is an "active context". A mismatch fails with "You're in live mode. Add --live…" (`ResolveCredentials`).
  - `stripe switch` changes the active account or sandbox. A context banner prints before requests (`PrintActiveContextBanner`).
  - Hidden `--api-base`, `--dashboard-base` and `--access-base` flags exist for QA. `--access-base` is allow-listed so it can't exfiltrate tokens ([pkg/cmd/root.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/cmd/root.go) `PersistentPreRunE`, [pkg/login/access_base.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/login/access_base.go)).

## 5. Output, errors, exit codes

- **JSON output:**
  - Response bodies go through `ansi.ColorizeJSON`, which runs `tidwall/pretty` and colors the result only when stdout is a TTY. Otherwise the raw body is printed unchanged ([pkg/ansi/ansi.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/ansi/ansi.go), [pkg/requests/base.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/requests/base.go) `performRequest`).
  - `--dark-style` switches the palette.
  - PDF responses are written to `<id>.pdf` instead of printed.
- **Color controls:** `--color on|off|auto`, plus `CLICOLOR` / `CLICOLOR_FORCE` ([pkg/ansi/ansi.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/ansi/ansi.go) `shouldUseColors`). I found no `NO_COLOR` handling in that function.
- **`--format`:** API/resource commands have none. Only `listen` and `logs tail` take `--format JSON`. `listen --print-json` is deprecated in favor of `--format json` plus `jq` ([pkg/cmd/listen.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/cmd/listen.go), [pkg/cmd/logs/tail.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/cmd/logs/tail.go)).
- **Request debugging:**
  - `-s/--show-headers` turns on a verbose transport that dumps the request and response headers ([pkg/stripe/verbosetransport.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/stripe/verbosetransport.go)).
  - `--dry-run` prints `{dry_run:{method,url,params,headers}}` with the bearer token redacted ([pkg/requests/base.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/requests/base.go) `BuildDryRunOutput`).
  - `-H` adds custom headers. `--log-level debug|trace` covers internals.
  - A `Stripe-Notice` response header is echoed to stderr.
- **Errors and exit codes:**
  - `Execute` prints errors to stderr and calls `os.Exit(1)` on any command error. Special-cased messages cover expired keys, `more_permissions_required`, login required (with auto-login on a TTY), and unknown commands ("Did you mean…") ([pkg/cmd/root.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/cmd/root.go)).
  - **Watch out:** resource and HTTP commands call `MakeRequest(..., errOnStatus=false)`. Only 401 becomes an error. Other 4xx/5xx bodies are printed as normal JSON and the function returns `nil`, so by code reading they exit 0 ([pkg/requests/base.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/requests/base.go) `performRequest`; [pkg/cmd/resource/operation.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/cmd/resource/operation.go)). The canary tests only assert exit 0 on success paths ([canary/api_test.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/canary/api_test.go)).
  - Errors are typed by `errorcategory` (UserInput, Auth, Network, Internal…), and a custom linter enforces it ([pkg/errorcategory/category.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/errorcategory/category.go), Makefile `lint`).

## 6. `listen` and `trigger`

- **Session:**
  - `listen` POSTs `/v1/stripecli/sessions` with `device_name`, `websocket_features[]=webhooks`, optional `filters`, and forward URLs.
  - The response is `{websocket_url, websocket_id, websocket_authorized_feature, secret, reconnect_delay, default_version, latest_version, …}` ([pkg/stripeauth/client.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/stripeauth/client.go), [pkg/stripeauth/messages.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/stripeauth/messages.go)).
  - `secret` is the `whsec_…` printed as "Ready! Your webhook signing secret is…". It doesn't change between restarts ([docs/cli/listen](https://docs.stripe.com/cli/listen)). `--print-secret` prints it and exits (`proxy.GetSessionSecret`, [pkg/proxy/proxy.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/proxy/proxy.go)).
- **Transport:** a gorilla websocket with ping/pong and reconnect (default 60 s) ([pkg/websocket/client.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/websocket/client.go)).
- **Delivery:**
  - Incoming `webhook_event` messages carry `event_payload` plus `http_headers`. Stripe has already computed `Stripe-Signature` server-side.
  - The CLI copies those headers onto the POST to `--forward-to` ([pkg/websocket/webhook_messages.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/websocket/webhook_messages.go), [pkg/proxy/endpoint.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/proxy/endpoint.go) `Post`).
  - It then sends back an `event_ack` and a `webhook_response` (status, body, headers) so the Dashboard can show the local endpoint's result ([pkg/proxy/webhook_event_processor.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/proxy/webhook_event_processor.go)).
- **Filtering and flags:**
  - `--events a,b`, `--all-snapshot`, `--all-thin`, `--events-from @self|@accounts|all`.
  - `--forward-connect-to`, `-H` headers, `--latest` (latest API version), `--use-configured-webhooks` (mirror the Dashboard endpoints), `--skip-verify`.
  - Since recent versions, `--forward-to` requires an explicit event selection ([pkg/cmd/listen.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/cmd/listen.go), [docs/cli/listen](https://docs.stripe.com/cli/listen)).
- **`events resend`** replays an event to the CLI session via `for_stripecli=true` (section 2).
- **`trigger` / `fixtures`:**
  - About 128 embedded JSON fixtures (`//go:embed triggers/*`, [pkg/fixtures/triggers.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/fixtures/triggers.go)).
  - Each fixture is `{_meta:{template_version}, fixtures:[{name,path,method,params}]}`. Later steps reference earlier responses with `${customer:id}` and env vars with `${.env:VAR|default}` ([pkg/fixtures/triggers/customer.subscription.created.json](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/fixtures/triggers/customer.subscription.created.json), [pkg/cmd/fixtures.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/cmd/fixtures.go)).
  - Flags: `--override step:path=val`, `--add`, `--remove`, `--skip step`, `--raw`, `--edit`, `--api-version`, `--stripe-account` ([pkg/cmd/trigger.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/cmd/trigger.go)).
  - Events are the natural result of real API calls. The CLI never fabricates an event.
  - Fixtures can't override protected headers ([pkg/fixtures/fixtures.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/fixtures/fixtures.go)).

## 7. Pagination, idempotency, versioning, expand

All of these are registered in `Base.InitFlags` ([pkg/requests/base.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/requests/base.go)):

- **Pagination:** list operations get `-l/--limit`, `-a/--starting-after` and `-b/--ending-before`. That is manual cursoring only; I found **no auto-paging or `--all`** anywhere in `pkg/`.
- **Idempotency:** `-i/--idempotency` sets `Idempotency-Key`. It warns when used on GET/DELETE. Nothing auto-generates a key.
- **Versioning:** `-v/--stripe-version` overrides the version. Otherwise v2 paths send the generated pinned version, preview commands send the preview version, and v1 sends nothing, so the account default applies (`computeVersionHeader`).
- **Connect headers:** `--stripe-account` and `--stripe-context`.
- **Expand:** `-e/--expand` (repeatable). It is sent as the `expand[]` param for v1 and isn't supported on v2.

## 8. Self-update, version check, telemetry, plugins

- **Version notice:**
  - `version`, `listen`, `trigger`, `fixtures` and `open` call `version.CheckLatestVersion()`. It asks the GitHub releases API once every 24 h, waits a 24 h grace period after a release (so package managers can catch up), prints install-method-specific upgrade advice, and is disabled by `STRIPE_NO_UPDATE_CHECK` ([pkg/version/version.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/version/version.go)).
  - The version string is injected via ldflags (`-X …/pkg/version.Version={{.Version}}`) and defaults to `master` ([.goreleaser/mac.yml](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/.goreleaser/mac.yml)).
- **Auto-update:**
  - Applies to install-script installs only. Package-manager installs get advice instead ([docs/cli/upgrade](https://docs.stripe.com/cli/upgrade), [pkg/autoupdate/config.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/autoupdate/config.go)).
  - After a command runs, `CheckForUpdate` stages a signed marker at most daily and skips major-version jumps.
  - On the next start, `ApplyIfPending` downloads the archive, verifies its checksum against the signed checksum file (RSA-3072 PKCS#1 v1.5 key embedded at `pkg/autoupdate/release-key.pub`), swaps the binary, and re-execs ([pkg/autoupdate/checker.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/autoupdate/checker.go), [updater.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/autoupdate/updater.go), [signature.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/autoupdate/signature.go), [docs/release-signing.md](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/docs/release-signing.md)).
  - Opt out with `STRIPE_NO_AUTO_UPDATE=1` or `auto_update = false` in config.toml.
- **Telemetry:**
  - An `AnalyticsTelemetryClient` POSTs to `https://r.stripe.com/0` (3 s timeout, async; overridable via `STRIPE_TELEMETRY_URL`) ([cmd/stripe/main.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/cmd/stripe/main.go), [pkg/stripe/analytics_telemetry.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/stripe/analytics_telemetry.go)).
  - Fields (`CLIAnalyticsEventMetadata`): invocation_id, user_agent, command_path, **flag names only (no values)**, merchant (`acct_…`), cli_version, os, arch, persistent machine_uuid, generated_resource, AI agent, agent host and version, install_method, tmux/screen, terminal program, and a bucketed http_outcome.
  - Events: "Command Invoked" (from `PersistentPreRunE`) and one API-request event per request, keyed by the `Request-Id` ([pkg/stripe/client.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/stripe/client.go)).
  - Sentry crash and error reporting goes to `errors.stripe.com`, with scrubbing ([pkg/reporting/](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/reporting/reporting.go)).
  - **Opt-out:** `STRIPE_CLI_TELEMETRY_OPTOUT=1|true` or `DO_NOT_TRACK=1|true` turns off both telemetry and Sentry ([cmd/stripe/main.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/cmd/stripe/main.go) `TelemetryOptedOut`). Dev builds (non-semver versions) also skip it.
- **Plugins:**
  - HashiCorp go-plugin: separate binaries talking gRPC with a per-plugin `MagicCookieValue` handshake.
  - A TOML manifest (`plugins.toml`) lists releases per OS/arch with a `Sum` checksum. Binaries are downloaded from Stripe's artifact host ([pkg/plugins/plugin.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/plugins/plugin.go)).
  - Installed plugins register as top-level commands at startup (`registerInstalledPlugins`, [pkg/cmd/root.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/cmd/root.go)). Known-but-missing plugins get hint or auto-install stubs ([pkg/cmd/pluginhints/](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/cmd/pluginhints)).
  - Plugins can call back into the core through `CoreCLIHelper` (login, config) ([pkg/plugins/core_cli_helper.go](https://github.com/stripe/stripe-cli/blob/78a032ff933e9924ff306123fbe373c1ee885c55/pkg/plugins/core_cli_helper.go)). Subprocesses are reaped on SIGINT/SIGTERM.

## Adopt / Adapt / Skip for teachmehipaa-cli

Our API, from `~/scratch/tmh-sdks/openapi/openapi.developer.json`, has these properties:

- OpenAPI 3.1, 56 operations, all with `operationId` and one of 15 tags. **No `x-` vendor extensions.**
- Servers: `api.tme.so/v1` and `api-teachmehipaa-dev.web.app/v1`.
- Auth: OAuth2 client-credentials (15-min JWT, no refresh) plus auth-code+PKCE via `console.teachmehipaa.com/oauth/authorize` (rotating refresh).
- Errors: RFC 9457 problem+json.
- Pagination: cursors named `cursor`, or `after` on events.
- Writes accept an `Idempotency-Key`.
- Custom methods use the AIP-136 `:verb` style (`:cancel`, `:renew`, `:remind`, `:resendInvite`, `:redrive`…).
- Long-running operations (AIP-151) are polled at `GET /organizations/{orgId}/operations/{operationId}`.
- Webhooks are signed with `x-tmh-*` headers: an HMAC-SHA256 over `POST\n<path+query>\n<timestamp>\n<body-hash>`, with a per-subscription secret.
- `GET /organizations/{orgId}/events?after=&type=` is the events pull log.

### Language recommendation

**Go, as a standalone binary, with its own thin generated client. Don't layer it on one of our SDKs.**

1. **Distribution decides it.** A CLI's main job is installing everywhere. Go cross-compiles static binaries (CGO only for the macOS keychain, as Stripe does with `CGO_ENABLED=1` on darwin) of about 15 MB. GoReleaser then gives us Homebrew, Scoop, winget, deb/rpm, Docker, notarization and signed checksums from YAML we can copy almost line for line from `.goreleaser/*.yml`. A Bun `--compile` binary built from `teachmehipaa-node` is roughly 60–100 MB and has weaker keyring support (it needs native addons or shelling out to `security`/`secret-tool`).
2. **Proven parts exist.** cobra, viper, zalando/go-keyring, `pkg/browser`, `golang.org/x/oauth2` (PKCE and client-credentials built in), gorilla/websocket, testify. Stripe, gh and flyctl show the shape. We can lift Stripe's patterns (generated `OperationSpec` table + generic executor, keyring fallback, non-interactive login JSON, signed self-update) directly. Stripe's code is Apache-2.0, so keep attribution if we copy anything.
3. **The SDKs don't fit the CLI's job.** None of our SDK repos (node/python/ruby/java/dotnet) is built yet, and a CLI needs a *dynamic* executor driven by spec metadata, not typed per-method SDK calls. Stripe's CLI doesn't use stripe-go either; it has its own `pkg/requests`. Our generator would output the cobra wiring plus an `OperationSpec` table from `openapi.developer.json`. Shared HTTP behavior (auth, retries, problem+json, idempotency) is about 1–2k lines of Go.
4. **Trade-off to accept:** our team writes TypeScript, not Go. Because about 70% of the command surface is generated, the handwritten Go is mostly auth, `events tail`, `--wait`, and output. If Go staffing is a hard no, the fallback is TypeScript on Bun, compiled with `bun build --compile`, reusing `@tmh/api-contracts` Zod schemas for validation. Expect bigger binaries and hand-rolled packaging (no GoReleaser equivalent).
